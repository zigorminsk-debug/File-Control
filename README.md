# File Control

Windows-служба с локальным HTML-интерфейсом для аудита создания, изменения и удаления файлов. Особое внимание уделено документам Microsoft Office (`docx`, `xlsx`, `pptx` и др.), включая временные `~$...`/`.tmp` файлы и схему сохранения через создание нового файла и удаление/замену старого.

## Почему логин пользователя определяется точно

`FileSystemWatcher` сообщает, **что** изменилось, но не сообщает, **кто** это сделал. Поэтому File Control читает события **4663** штатного журнала Windows Security. В событии Windows фиксирует `SubjectDomainName` и `SubjectUserName` из токена безопасности операции. Для файлов в SMB-шаре это доменный логин удалённого пользователя, а не учётная запись службы и не приблизительное сопоставление активной сессии.

> Журнал будет полным только при включённых Object Access Audit Policy и SACL на каждой отслеживаемой папке. Скрипт установки делает это автоматически. Служба запускается как LocalSystem, поскольку чтение Security log требует повышенных прав.

## Возможности

- создание, изменение и удаление с датой/временем, `DOMAIN\login`, именем, путём и процессом;
- журнал SQLite в WAL-режиме и защита от повторной записи одного события;
- распознавание расширений и временных файлов Office;
- работа Windows Service в фоне и автозапуск;
- локальная панель `http://localhost:8787`, фильтры по пользователю, документу и диапазону дат;
- ежедневный автономный интерактивный HTML-отчёт, по умолчанию в 01:00;
- отчёт открывается без сервера и поддерживает поиск по документу, пользователю и дате;
- автоматическая self-contained сборка Windows x64 через GitHub Actions.

## Установка

1. На странице GitHub Actions скачайте артефакт `FileControl-win-x64` и распакуйте его.
2. Запустите PowerShell **от имени администратора**:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\Install-Service.ps1 -MonitoredPath 'D:\Shares\Documents','E:\Accounting'
```

3. Отредактируйте `C:\Program Files\FileControl\appsettings.json`, если нужны другие параметры, затем выполните `Restart-Service FileControl`.
4. Откройте `http://localhost:8787` на сервере. Интерфейс намеренно слушает только loopback и не выставляет журнал в сеть. Для удалённого доступа используйте защищённый reverse proxy с аутентификацией или RDP.

Если папка добавлена позже, примените аудит и обновите конфигурацию:

```powershell
.\scripts\Install-Auditing.ps1 -Path 'D:\NewShare'
Restart-Service FileControl
```

## Настройка

Секция `FileControl` в `appsettings.json`:

| Параметр | Назначение |
|---|---|
| `MonitoredPaths` | папки, события которых принимаются из Security log |
| `DatabasePath` | файл SQLite |
| `ReportDirectory` | каталог ежедневных HTML-отчётов |
| `ReportHour` | локальный час формирования (0–23) |
| `RetentionDays` | срок хранения событий |
| `IgnoredUsers` | системные учётные записи, которые не включаются в журнал |

Отчёт за произвольный день можно создать вручную:

```powershell
Invoke-RestMethod -Method Post http://localhost:8787/api/reports/2026-10-16
```

## Важное о событиях Office

Office обычно создаёт временный файл, записывает его, удаляет/переименовывает старый документ и заменяет его новым. File Control намеренно сохраняет эти атомарные операции, а не скрывает их за одним синтетическим событием: так аудит остаётся доказуемым и не теряет удаление. В колонке описания временные и блокировочные файлы отмечаются отдельно. Несколько строк при одном сохранении документа — ожидаемое поведение.

Создание определяется как запись в файл, время создания которого совпадает со временем события; прочие операции записи отмечаются как изменение. Чтения не сохраняются.

## Диагностика

```powershell
Get-Service FileControl
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4663} -MaxEvents 5
Get-WinEvent -LogName Application | Where-Object ProviderName -like '*FileControl*'
```

Если 4663 отсутствуют, повторно запустите `Install-Auditing.ps1` от администратора и проверьте, что применённая доменная Group Policy не отключает подкатегорию **File System**.

## Разработка

Требуется .NET 8 SDK и Windows для реального чтения Security log:

```powershell
dotnet run --project src/FileControl
```

На других ОС интерфейс и база запускаются, но монитор Security log отключается с предупреждением.
